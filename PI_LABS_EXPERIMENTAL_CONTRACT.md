# PI Labs Experimental Contract

PI Labs exists to transfer verified improvements into PI, not to accumulate impressive research documents.

## Permanent research engines

1. **Execution Lab** — failure autopsies, continuity, recovery, duplicate-work prevention, retry strategy.
2. **Connectome Lab** — minimum reliable circuits, sparse specialist/model activation, verification/recovery topology.
3. **Capability Lab** — standardized tournaments for models, tools, providers, frameworks and local execution paths.
4. **Compute Lab** — workload telemetry, memory/compute bottlenecks, software optimization first; hardware only after measured justification.

## Scientific loop

Every experiment must contain:
- question;
- baseline;
- falsifiable hypothesis;
- representative task set;
- metrics;
- experiment configuration;
- raw/result evidence location;
- comparison;
- failure cases;
- reproducibility status;
- decision: PROMOTE, CONTINUE, HOLD, or KILL.

Required metrics where applicable:
- task success/accuracy;
- verified completion rate;
- latency;
- model/tool calls;
- tokens/compute;
- cost;
- recovery rate;
- repeated-failure rate;
- evidence quality.

A research note, model opinion, synthetic PASS, or architecture diagram is not a discovery.

## Promotion boundary

LABS EXPERIMENTAL → Nandi independent verification → Engineering hardening/regression coverage → Krishna routing decision → Product.

Labs may not directly label an experimental path production-ready.

## Initial missions

### L1 — Execution Autopsy
Use real PI failures and unfinished missions. Produce failure fingerprints and safeguards that prevent recurrence. First transferred safeguard: repeated identical failure fingerprints must not trigger blind repeated retries.

### L2 — Connectome Benchmark V1
Compare current orchestration with a minimum-reliable-circuit variant on the same representative workload. Do not claim improvement until the comparison is reproducible.

### L3 — Capability Tournament
Compare candidate models/tools/providers using the same PI workload and metrics. Recommend winners per task class; never declare one permanent universal winner from a single benchmark.

### L4 — Compute Telemetry
Measure recurring expensive operations before proposing custom hardware. Software optimization precedes simulation; simulation evidence precedes FPGA; FPGA evidence precedes any ASIC program.

## Success metric

PI Labs practical impact = verified improvements transferred into production.

If zero improvements are independently verified and transferred, Labs practical improvement for that period is zero, regardless of document count.
